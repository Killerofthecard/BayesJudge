# BayesJudge User Guide

This project implements a strict Bayesian evaluation framework based on particle filtering. It supports running experiments on synthetic data (Simulation) and real-world data (SummEval) to detect and correct position bias in LLM judges.

---

## 1. Synthetic Data Generation (`generate_simulated_data.py`)

### 1.1 Core Class: `SyntheticDataGenerator`

`SyntheticDataGenerator` generates observed labels by forward-sampling from ground-truth parameters. The label convention is unified as follows:

| Label | Meaning |
|-------|---------|
| `A` | Model A is better than Model B |
| `C` | Tie |
| `B` | Model B is better than Model A |

### 1.2 Main API

```python
from generate_simulated_data import SyntheticDataGenerator

# 1. Initialize the generator
generator = SyntheticDataGenerator(seed=42)

# 2. Configure ground-truth parameters
generator.setup_ground_truth(
    n_samples=1000,                          # Total number of samples
    human_raters=[...],                      # Human rater configs (optional, see examples below)
    llm_judges=[...],                        # LLM judge configs (optional, see examples below)
    class_ratios={'A': 0.4, 'B': 0.4, 'C': 0.2}  # Class ratios (must sum to 1)
)

# 3. Generate the dataset
dataset = generator.generate_dataset(
    save_path='./dataset/synthetic_1000.json',  # Save path (optional)
    perfect_llm=False                           # Whether to use a perfect LLM (noise-free)
)

# 4. Print statistics
generator.print_statistics(dataset)
```

### 1.3 Human Rater Configuration

Each human rater is defined by a **3×3 confusion matrix** `C_r`, where:
- **Rows** = True classes `[A, C, B]`
- **Columns** = Observed classes `[A, C, B]`

```python
human_raters = [
    {
        'name': 'expert_rater',
        'confusion_matrix': [
            [0.98, 0.01, 0.01],   # True A: 98% judged as A
            [0.02, 0.96, 0.02],   # True C: 96% judged as C
            [0.01, 0.01, 0.98]    # True B: 98% judged as B
        ],
        'description': 'Expert rater (98% accuracy)'
    },
    {
        'name': 'noisy_rater',
        'confusion_matrix': [
            [0.70, 0.20, 0.10],
            [0.30, 0.60, 0.10],
            [0.20, 0.20, 0.60]
        ],
        'description': 'Noisy rater (average 63% accuracy)'
    }
]
```

### 1.4 LLM Judge Configuration

Each LLM judge is defined by a **position-bias coefficient `beta`**, corresponding to the swap-design likelihood function in Section 2.2.2 of the paper:

```python
llm_judges = [
    {
        'name': 'gpt4',
        'beta': 0.2,            # Low position bias
        'description': 'GPT-4 level (beta=0.2)'
    },
    {
        'name': 'small_llm',
        'beta': 1.2,            # High position bias
        'description': 'Small model (beta=1.2, biased toward the first position)'
    }
]
```

> **Interpretation**: `beta > 0` means the LLM tends to prefer the option shown **first**. The larger the `beta`, the stronger the position bias.

### 1.5 Complete Example

```python
from generate_simulated_data import SyntheticDataGenerator

generator = SyntheticDataGenerator(seed=42)
generator.setup_ground_truth(
    n_samples=1000,
    human_raters=[
        {'name': 'rater_expert', 'confusion_matrix': [[0.90,0.05,0.05],[0.10,0.80,0.10],[0.10,0.05,0.85]], 'description': 'Expert'},
        {'name': 'rater_novice', 'confusion_matrix': [[0.50,0.25,0.25],[0.30,0.40,0.30],[0.25,0.25,0.50]], 'description': 'Novice'}
    ],
    llm_judges=[
        {'name': 'llm_strong', 'beta': 0.0, 'description': 'Strong LLM'},
        {'name': 'llm_weak',  'beta': 2.0, 'description': 'Weak LLM (high position bias)'}
    ],
    class_ratios={'A': 0.4, 'B': 0.4, 'C': 0.2}
)

dataset = generator.generate_dataset(
    save_path='./dataset/synthetic_1000_custom.json',
    perfect_llm=False
)
generator.print_statistics(dataset)
```

Two files will be generated after running:
- `synthetic_1000_custom.json` —— Data file
- `synthetic_1000_custom_config.json` —— Config file (contains ground-truth parameters for later comparison with learned parameters)

## 2. Downloading the SummEval Dataset

### 2.1 Data Source

SummEval is a classic text-summarization quality evaluation dataset, containing:
- Summaries generated by multiple models for the same article
- Expert annotations (3 annotators)
- Crowd-worker annotations (5 annotators)

### 2.2 Download Methods

Please obtain the raw data file `model_annotations.aligned.paired.jsonl` from one of the following sources:

**Method 1: Hugging Face**
```bash
pip install datasets
python -c "from datasets import load_dataset; ds = load_dataset('mteb/summeval'); ds.save_to_disk('./summeval_raw')"
```

**Method 2: Official Repository**
- GitHub: [https://github.com/Yale-LILY/SummEval](https://github.com/Yale-LILY/SummEval)
- After downloading, locate the aligned annotation file, usually named `model_annotations.aligned.paired.jsonl`

Place the downloaded file in the project root or any path for the next conversion step.

> **File Format Description**: The raw file is in JSON Lines format. Each line is a record containing fields such as `text` (source article), `decoded` (model-generated summary), `model_id` (model identifier), `expert_annotations` (list of expert scores), `turker_annotations` (list of crowd-worker scores), etc.

## 3. Converting SummEval to Pairwise Format (`convert_summeval_to_pair.py`)

### 3.1 Functionality

The raw SummEval data consists of **multiple model summaries for the same text**. It needs to be converted into a **pairwise comparison** format before being fed into the Bayesian evaluation framework.

Conversion logic:
1. Group model outputs by the same `text` into groups of size `group_size` (default 16).
2. Within each group, generate all pairwise combinations between models, `C(n, 2)`.
3. For each pair, compute the average score from expert / crowd-worker multi-dimensional ratings and determine the winner.

### 3.2 Usage

```python
from convert_summeval_to_pair import convert_to_pairwise_json

convert_to_pairwise_json(
    input_file="model_annotations.aligned.paired.jsonl",   # Raw SummEval file
    output_file="summeval_pairwise.json",                  # Output pairwise file
    group_size=16                                          # Group size (default 16)
)
```

Or run directly from the command line:
```bash
python convert_summeval_to_pair.py
```

### 3.3 Output Format

The generated `summeval_pairwise.json` is a JSON array. Each element has the following structure:

```json
{
  "unique_id": "eval_000000_modelA_vs_modelB",
  "question_id": "...",
  "model_a": "model_id_1",
  "model_b": "model_id_2",
  "text": "Original article text...",
  "model_a_output": "Summary generated by model A...",
  "model_b_output": "Summary generated by model B...",
  "judges": ["expert_1", "expert_2", "expert_3", "turker_1", ..., "turker_5"],
  "winners": ["model_a", "tie", "model_b", ...],
  "score_details": { ... }
}
```

> **Note**: Values in `winners` are `model_a` / `model_b` / `tie`, which are mapped to framework labels `A` / `B` / `T` in the experiment scripts.

## 4. Running Experiments

The project provides two experiment entry scripts for **synthetic data** and **real-world data** respectively:

| Script | Data Type | Description |
|--------|-----------|-------------|
| `simulation_exp.py` | Synthetic | Can compare learned parameters with preset ground truth |
| `summeval_exp.py` | SummEval real data | Supports LOHO (Leave-One-Human-Out) prediction |

### 4.1 Synthetic Data Experiment: `simulation_exp.py`

#### Basic Usage

```bash
python simulation_exp.py \
  --data ./dataset/synthetic_1000_custom.json \
  --n_train 800 \
  --n_particles 300 \
  --llm_models llm_strong,llm_weak
```

#### Common Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `--data` | `./dataset/synthetic_1000_custom.json` | Path to the synthetic data file |
| `--config` | `None` (auto-find `_config.json`) | Config file path for loading ground-truth parameters |
| `--n_train` | `800` | Number of training samples (remaining go to the test set) |
| `--llm_models` | `None` (all) | Specify LLMs to participate in modeling, comma-separated |
| `--n_particles` | `300` | Number of particles for particle filtering |
| `--lambda_diag` | `1.0` | Diagonal element of the human confusion matrix prior |
| `--lambda_off` | `0.0` | Off-diagonal element of the human confusion matrix prior |
| `--update_human` / `--no_update_human` | Update | Whether to update the human bias matrix `C_r` during training |
| `--update_llm` / `--no_update_llm` | Update | Whether to update the LLM bias parameter `beta` during training |
| `--output_dir` | `./outputs` | Output directory |
| `--output_name` | `None` | Prefix for output file names |
| `--live_plot` | Off | Enable real-time convergence curve plotting |

#### Running Examples

```bash
# Only update human parameters, fix LLM parameters
python simulation_exp.py \
  --data ./dataset/synthetic_1000_custom.json \
  --n_train 800 \
  --update_llm \
  --no_update_human

# Use fewer particles for quick validation
python simulation_exp.py \
  --data ./dataset/synthetic_500.json \
  --n_train 400 \
  --n_particles 100 \
  --no_verbose
```

#### Experiment Pipeline

1. **Training Phase**: The first `n_train` samples are fed sequentially. The particle distribution, human confusion matrix `C_r`, and LLM bias `beta` are updated online.
2. **Test Phase**: The remaining samples are used for inference only (fixed parameters). **Predictive log-likelihood** and **perplexity** are computed.
3. **Parameter Comparison**: If a `_config.json` is provided, the script automatically compares learned `beta` / `C_r` with the preset ground truth, reporting MSE / RMSE / Frobenius norm.

#### Output Files

After the experiment, the following are generated in the `outputs/` directory:
- `{experiment_name}_uh{0/1}_ul{0/1}_results.json` —— Complete experiment results (including verdict distribution and parameter history for each sample)
- `{experiment_name}_uh{0/1}_ul{0/1}_variance.png` —— Variance convergence curve (if `--live_plot` is enabled)
- `{experiment_name}_uh{0/1}_ul{0/1}_beta.png` —— Beta coefficient convergence curve (if `--live_plot` is enabled)

> `uh1` = update human parameters, `ul1` = update LLM parameters

### 4.2 Real Data Experiment: `summeval_exp.py`

#### Basic Usage

```bash
python summeval_exp.py \
  --data summeval_pairwise.json \
  --n_train 800 \
  --n_particles 300 \
  --model gpt-4o-mini
```

#### Common Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `--data` | `dataset/summeval_pairwise_1000.json` | Path to the SummEval pairwise data file |
| `--n_samples` | `None` (all) | Total number of samples to use |
| `--n_train` | `800` | Number of training samples |
| `--model` | `gpt-4o-mini` | Model name for pre-computed LLM judgments in the dataset. **Supports comma-separated multi-model joint modeling** (e.g., `gpt-4o-mini,gpt-4o`) |
| `--human_judges` | `None` (all) | Specify human judges to participate, comma-separated (e.g., `expert_1,expert_2,turker_1`) |
| `--human_prior` | `None` | Path to a custom human prior confusion matrix JSON file |
| `--n_particles` | `300` | Number of particles |
| `--lambda_diag` | `1.0` | Prior diagonal element |
| `--lambda_off` | `0.0` | Prior off-diagonal element |
| `--update_human` / `--no_update_human` | Update | Whether to update the human bias matrix |
| `--update_llm` / `--no_update_llm` | Update | Whether to update the LLM bias parameter |
| `--zero_human_likelihood` | Off | Set human log-likelihood to 0 during testing (ablation) |
| `--zero_llm_likelihood` | Off | Set LLM log-likelihood to 0 during testing (ablation) |
| `--output_dir` | `./outputs` | Output directory |
| `--live_plot` | Off | Enable real-time plotting |

#### Running Examples

```bash
# Single-model evaluation
python summeval_exp.py \
  --data summeval_pairwise.json \
  --model gpt-4o-mini \
  --n_train 800 \
  --n_particles 300

# Multi-model joint modeling
python summeval_exp.py \
  --data summeval_pairwise.json \
  --model gpt-4o-mini,gpt-4o \
  --n_train 800 \
  --update_llm \
  --update_human

# Use only expert annotators
python summeval_exp.py \
  --data summeval_pairwise.json \
  --human_judges expert_1,expert_2,expert_3 \
  --model gpt-4o-mini

# Ablation: disable LLM likelihood during testing
python summeval_exp.py \
  --data summeval_pairwise.json \
  --model gpt-4o-mini \
  --zero_llm_likelihood
```

#### Experiment Pipeline

Similar to `simulation_exp.py`, the pipeline is divided into a **training phase** (parameter update) and a **test phase** (fixed-parameter inference). In addition, `summeval_exp.py` computes:

- **LOHO (Leave-One-Human-Out) Prediction Accuracy**: For each test sample, one human annotator's label is left out in turn. The verdict distribution is inferred from the remaining labels, and the left-out annotator's label is predicted. Prediction accuracy is then aggregated.

#### Output Files

- `{experiment_name}_uh{0/1}_ul{0/1}_results.json` —— Complete results (including LOHO statistics)
- `.log` file —— Full command-line output log (auto-saved)
- Convergence curve images (if `--live_plot` is enabled)

## 5. Complete Pipeline Example

```bash
# Step 1: Generate synthetic data
python generate_simulated_data.py

# Step 2: Run synthetic data experiment
python simulation_exp.py \
  --data ./dataset/synthetic_1000_custom.json \
  --n_train 800 \
  --llm_models llm_strong,llm_weak

# Step 3: Convert SummEval to pairwise (assuming raw data has been downloaded)
python convert_summeval_to_pair.py

# Step 4: Run SummEval experiment
python summeval_exp.py \
  --data summeval_pairwise.json \
  --model gpt-4o-mini \
  --n_train 800
```
